# Lab-Politicas-de-acesso-Azure

# RBAC( CONTROLE DE ACESSO BASEADO EM FUNÇÃO
 * FUNÇÕES:
  - EM VEZ DE DAR PERMISSÕES INDIVIDUAIS, VOCÊ ATRIBUI UMA FUNÇÃO.
    
 * ESCOPO:
  - VOCÊ DEFINE ONDE A FUNÇÃO SE APLICA.
   
 * HERANÇA:
  - CASO CONCEDA ACESSO A ALGUÉM EM UMA PASTA, ESSA PESSOA TERÁ ACESSO A         TUDO DENTRO DELA.

# AZURE POLICY (POLÍTICAS DE GOVERNANÇA)
 * RESTRIÇÕES:
   - VOCÊ PODE PROIBIR A CRIAÇÃO DE MÁQUINAS VIRTUAIS MUITO CARAS PARA NÃO        GASTAR CRÉDITOS DE ESTUDANTE.
     
 * LOCALIZAÇÃO:
   - PODE FORÇAR QUE TODAS OS SEUS DAODS FIQUEM EM SERVIDORES NO BRASIL         PARA REDUZIR A LATÊNCIA.
     
 * PADRONIZAÇÃO:
   - GARANTE QUE TODOS OS RECURSOS CRIADOS TENHAM ETIQUETAS (TAGS) PARA           ORGANIZAÇÃO.

# AZURE AD / MICROSOFT ENTRA ID (PORTEIRO DIGITAL)
 * IDENTIDADE ÚNICA:
   - VOCÊ USA UMA ÚNICA CONTA PARA ACESSAR TODOS OS SERVIÇOS.
     
 * MFA (AUTENTICAÇÃO DE MÚLTIPLOS FATORES)
   - EXIGE UMA SEGUNDA CONFIRMAÇÃO (SMS POR EXEMPLO) PARA EVITAR INVASÕES.
     
 * ACESSO CONDICIONAL:
   - REGRAS INTELIGENTES QUE BLOQUEIAM O ACESSO SE ALGUÉM TENTAR LOGAR DE       UM PÁIS ESTRANHO OU DE UM DISPOSITIVO NÃO CONFIÁVEL.

 # PIM (PRIVILEGED IDENTITY MANAGEMENT)
  * ACESSO "JUST-IN-TIME":
    - O ACESSO DE ADMINISTRADOR NÃO FICA ATIVO O TEMPO TODO; VOCÊ SOLICITA       APENAS QUANDO PRECISA USAR.
      
  * APROVAÇÃO:
    - OUTRA PESSOA PODE PRECISAR APROVAR SUA SOLICITAÇÃO DE ACESSO               ADMINISTRATIVO.
      
  * HISTÓRICO:
    - TUDO O QUE UM ADMINISTRADOR FAZ É REGISTRADO PARA AUDITORIA.
   
  # BLOQUEIOS DE RECURSOS (RESOURCE LOCKS)
   * CanNotDelete:
     - VOCÊ PODE LER E MODIFICAR O RECURSO, MAS NÃO PODE EXCLUÍ-LO POR            ACIDENTE.
   * ReadOnly:
     - VOCCÊ SÓ PODE VISUALIZAR O RECURSO, SEM FAZER NENHUMA ALTERAÇÃO.
